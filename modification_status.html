#22 — Fixed false "active appointment" conflicts (reference-numbering bug)

Verified working

2026-09-29 · Scope: backend (references, appointments) + bootstrap message + frontend race guard

What changed
  • You hit "The complaint already has an active appointment" while scheduling CMP-260929-003, even though it had never been scheduled before.
  • Root cause — appointment references are formatted APT-YYYY-00001 (year only), but the counter handing out the next number was keyed by the exact appointment date. Two appointments on different dates in the same year each counted from 1 independently, so their references collided (both became APT-2026-00001). The resulting database duplicate-key error was mislabeled as "already has an active appointment" — an unrelated, misleading explanation. There was never a real scheduling conflict.
  • Fixed — the appointment / job-card / quotation / inspection / warranty-approval counters now key by 1 January of the year (matching what the reference format encodes). Migration 016 seeds the new counters from what's already been issued. Complaint references were unaffected (they already encode the full date).
  • Even if a reference collision were ever to recur, it's no longer mislabeled as an appointment conflict — it now reports the real problem.
  • Also fixed the stale bootstrap error wording ("consumed for this process") left over from before Modification #20 made bootstrap DB-backed and permanent — it now says an admin account already exists and to sign in with it.
  • Also fixed a UI race in the Schedule-appointment form: navigating to a different complaint while an earlier schedule request was still in flight could stamp that request's result onto the complaint you'd since moved to. The handler now only updates the screen if you're still viewing the complaint the request was for.
